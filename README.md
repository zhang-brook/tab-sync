# Tab Sync - 浏览器标签页同步工具

浏览器扩展 + 后端，用于管理大量打开的标签页、跨设备同步、工作组归类与去重。

## 组件

| 目录 | 说明 |
|------|------|
| `browser-extension/` | 浏览器扩展（Vue 3 + Element Plus + Vite + CRXJS + MV3） |
| `server/` | 轻量后端（Go + Gin + SQLite），自部署的标签页同步服务 |

## 项目背景

其实这个项目最早灵感起源于 2024 年，最早以 tab-manager 命名，创建于 2024 年 10 月 4 日。

最初希望解决的问题是，我在使用浏览器的时候，经常习惯打开很多个标签页（那时大概得有 1000+ 的样子），于是会导致电脑内存占用很高，电脑卡顿且发热严重。但那时 AI 并没有这么成熟，而我当时也对浏览器扩展开发一知半解，所以只是匆匆创建了项目，然后尝试开发了一下就暂时搁置了（当时选择的是 nodejs 作为后端，前端浏览器扩展并没有使用框架，甚至都没用到 npm，就是纯 HTML + JavaScript + CSS）。

但其实我一直想着这件事，直到 2026 年 4 月，那时候 AI 已经比较厉害了，于是我开了一个月的 Qoder Pro 订阅。创建了一个新的项目叫做 tab-sync，然后让 AI 帮我选择了当前的这个 CRXJS 扩展开发框架。那时计划是纯浏览器侧存储，所以没有规划后端。

但随着 AI 编码深入，我发现 AI 确实有些力不从心了，改这里改那里，改了好久，也没改好，总是有些奇怪的bug。于是又搁置了，但项目框架保留下来了。

2026 年 6 月，我又重启了这个项目，这个时候 AI 能力又强大了不少，于是再次重启。先是进一步完善扩展功能。然后考虑到，未来可能会有多个浏览器（甚至多台电脑）的标签页都希望能够一起同步起来，这样还可以变相实现标签页的跨端同步，也方便去重，统计等，于是创建了后端项目。这次后端选择使用 Go 语言，使用 Gin 框架，并使用 SQLite 作为数据库。

经过不懈努力，感觉扩展功能主键能够满足自己的使用需求了。未来，我会自己先使用一段时间，边使用边优化，待功能进一步完善，并稳定后，会考虑将扩展发布到 Edge 和 Chrome 和扩展商店，并进一步推广。
